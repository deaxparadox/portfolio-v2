# Chapter 5

# Application Structure

---

## Objective

This document defines the application structure.

Unlike the Design Bible, this document is implementation-oriented.

It should answer:

- What are we building?
- How is it organized?
- What belongs where?
- What does each module own?
- How do different parts communicate?

No implementation details should appear here.

---

# 1. Workspace Architecture

```

```
Browser

┌─────────────────────────────────────────────────────────────┐
│                                                             │
│ Invisible Root Layout                                       │
│                                                             │
│ ┌────────────────────────────────────────────────────────┐  │
│ │ Primary Workspace                                      │  │
│ │                                                        │  │
│ │  Navigation                                             │  │
│ │  Active Route                                           │  │
│ │                                                        │  │
│ └────────────────────────────────────────────────────────┘  │
│                                                             │
│ ┌────────────────────────────────────────────────────────┐  │
│ │ Companion Workspace                                    │  │
│ │                                                        │  │
│ │  Deax                                                  │  │
│ │                                                        │  │
│ └────────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Root Layout is invisible.

Its only responsibility is positioning workspaces.

---

# 2. Primary Workspace

Responsibilities

- Navigation
- Routing
- Workspace scrolling
- Content rendering
- Shared layout
- Theme awareness

Must never know implementation details of Deax.

Communication occurs only through shared application events.

---

# 3. Companion Workspace

Responsibilities

- Chat
- Voice
- Session management
- Context awareness
- Navigation requests

The companion never renders portfolio content.

---

# 4. Navigation

Navigation belongs to the Primary Workspace.

It resizes together with the workspace.

Navigation is persistent.

Navigation never remounts during route changes.

---

# 5. Workspace Rules

Only workspace containers scroll.

Browser scrolling is disabled.

Every page must fit inside the workspace layout.

---

# 6. Routing

Every section owns a URL.

Examples

/

Featured

/projects

/projects/:slug

/experience

/resume

/engineering

/contact

/search

Assistant visibility is NOT routing.

Assistant state belongs to application state.

---

# 7. Module System

Pages do not own UI.

Modules own UI.

Example

Project Module

↓

used by

Homepage

↓

Project Page

↓

Search Results

↓

Recommendations

Each module has one responsibility.

---

# 8. Loading

Every route provides

- Skeleton
- Error
- Empty
- Loaded

states.

No blank screens.

---

# 9. Future Expansion

The architecture must allow adding

- Notes
- Articles
- Timeline
- Playground
- Lab

without changing the workspace architecture.

Only modules should be added.

Never redesign the layout.

---

# End Goal

The application should feel like

one workspace,

not

a collection of webpages.
